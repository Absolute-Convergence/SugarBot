# SugarBot Operator Registry (capabilities of this build)

Modules loaded: `cmp`, `core`, `logic`, `ts`

Type legend: `num` = numeric series, `bool` = boolean series

## AI Contract (PlanSpec JSON)

Use only this dump as capability truth for this build.
If a field/op is not documented here, do not infer it.

### Hard Guardrails (must follow)
- PlanSpec is a strict graph DSL: nodes + ids + bindings.
- `args[]` must contain exact prior node ids only (plain strings).
- Unary bool ops (for example `logic.not`) require dedicated nodes.
- `op` must exist in this registry; no user-defined ops in PlanSpec JSON.
- Data input is not limited to OHLC candles; close-only single-value tabular vectors are also supported.
- core.volume is not supported.
- core.close produces one numeric, index-aligned 1D time-series vector.
- Deep composition across numeric and bool graphs is supported.
- Plan execution is deterministic; Monte Carlo sweep is non-deterministic unless `seed > 0`.
- Sweep keys must match the documented schema exactly (including `engine_config`).
- JSON parsing/validation is strict: wrong types/arity/refs/bounds fail compilation.
- Custom PlanSpec uses a single JSON file.
- Anything not documented in this dump is unsupported for this build.

### Root schema (v1)
Required:
- `bindings` (object)

Common fields:
- `version` (int, default 1)
- `name` (string)
- `trade_mode` (string: LongOnly | LongShort)
- `exec_settings` (object)
- `params` (object)
- `numeric_nodes` (array<NodeSpec>)
- `bool_nodes` (array<NodeSpec>)
- `sweep` (object, optional)

### NodeSpec
- `id` (string, unique per node list)
- `op` (string; must exist in this registry)
- `args` (array<string>; order must match op signature)
- `params` (object; literals or `{ "ref": "paramName" }`)

### Type/wiring rules
- `numeric_nodes` may only consume numeric node ids.
- `bool_nodes` may consume bool or numeric ids depending on each op signature.
- `logic.*` inputs are bool; `cmp.*` inputs are numeric.
- `args` count must match op signature exactly.
- `args` entries are node ids only (never inline expressions like `cmp.cross_up(c, hi_prev)`).

logic.not also requires its own dedicated node (see Example 4 for trend_up / trend_dn pattern).

### Important limitations
- No user-defined ops in PlanSpec JSON.
- No include/import/multi-file PlanSpec composition.
- Param objects are only valid as `{ "ref": "..." }` (no expression objects).
- `core.precomputed_num` / `core.precomputed_bool` may be unavailable in custom plans; prefer standard ops.

### AI preflight checklist
- Root is valid JSON object (no comments, no trailing garbage).
- `bindings` exists; each binding value is a string.
- Node ids are unique per list and all referenced ids exist.
- Every `op` exists in this registry and `args` arity/type matches signature.
- All strings in every `args[]` array exactly match an earlier node id (plain string, no extra text).
- Required op params are present with correct types and bounds.
- Every `{ "ref": "k" }` resolves to a top-level `params.k` value.
- If sweep is enabled, `sweep.params` is non-empty and valid.

## Sweep Configuration

- `sweep.enabled` (bool, optional)
- `sweep.top_k` (int > 0, optional)
- `sweep.max_evals` (int > 0, optional)
- `sweep.objective` (string: `pnl` | `pnl_dd`, optional)
- `sweep.dd_weight` (float, optional; used for `pnl_dd`)
- `sweep.engine` (string: `exhaustive` | `coarse_fine` | `monte_carlo`, optional)
- `sweep.params` (object): map `paramName -> range`
- `sweep.engine_config` (object, optional)
  - `coarse_fine`:
    - `k_stage1`, `k_stage2` (int > 0)
    - `depollute_stage1`, `dedupe_stage2` (bool)
    - `suppression_hops`, `stage2_hops` (int > 0)
    - `stage1_stride` (int >= 0)
  - `monte_carlo`:
    - `draws` (int > 0)
    - `seed` (int >= 0)
    - `dedupe` (bool)
    - `top_k` (int > 0, optional)

Range forms:
- Discrete: `{ "values": [5,10,20], "is_int": true }`
- Stepped : `{ "min": 5, "max": 50, "step": 5, "is_int": true }`

Monte Carlo note:
- Monte Carlo search is stochastic.
- If `seed=0`, runs are non-deterministic.
- If `seed>0`, sampling is reproducible for the same build/data/config.
